# Home Assistant 2026.11 compatibility audit

Scope: source, manifests, config flows, service handlers, and entity lifecycle methods were checked against relevant Home Assistant Core 2026.9–2026.11 contributor announcements. The change in this PR addresses the new entity-ID lifecycle behavior; CI remains responsible for validating hassfest, HACS, and the full tests.

## Changed

- Sensor and switch entities implement `async_entity_id_changed`, opting in to Home Assistant 2026.11's in-place entity-ID updates.
- The entities' dispatcher subscriptions are keyed by config-entry ID rather than entity ID, so a rename does not require re-registering them.
- The hook delegates to the base-class implementation when available and safely does nothing on older Home Assistant versions where the hook is absent.
- Regression tests exercise the hook on both entity types.

## Checked, not otherwise affected

- **Device registry config-entry properties:** no references to `DeviceEntry.config_entries`, `config_entries_subentries`, or `primary_config_entry` were found.
- **Config-flow reload deprecation:** the options flow saves with `async_create_entry`; it does not combine a config-entry update listener with `async_update_reload_and_abort` or another config-flow reload method.
- **Config-entry callback return values:** the setup/unload functions returning booleans remain supported for custom integrations; this alone does not require a minimum-version increase.
- **Manifest and translations:** no manifest field or translation API change requiring a 2026.9–2026.11 migration was identified.
- **Minimum HA version:** unchanged to preserve compatibility with existing HACS users; the new hook is guarded for older releases.
